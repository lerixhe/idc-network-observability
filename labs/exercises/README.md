# 习题 · 自己写一遍

`labs/` 下 21 个实验是**参考实现**：代码写好了，跑一遍看输出，读 README 的坑列表。它们适合「先看懂」。

这个目录下是**留白版**：同一个实验，只留一个或两个函数给你写，其余给定。它们适合「再写一遍」。同一件事，看一遍与写一遍的差距，比看起来大。

## 四个习题

| 习题 | 对应课 | 要写什么 | 参考实现 |
|---|---|---|---|
| [`01-portstate`](./01-portstate) | 04–07 | 六成因判定树 + 抖动计数 + 重启剔除 | `../01-portstate` |
| [`07-counters`](./07-counters) | 18、36 | 三种速率算法 + 四类错包归因 | `../07-counters` |
| [`11-endpoint`](./11-endpoint) | 27 | ARP → FDB → 台账的三表联查 | `../11-endpoint` |
| [`15-tools-parse`](./15-tools-parse) | 41、43、45 | 列头驱动的解析布局 | `../15-tools-parse` |

选这四个的理由：它们的答案都是**判断力**，不是样板代码。判定树的顺序、回绕补正的圈数、三表联查先试哪个 MAC、列头空值怎么切——抄一遍没用，写错过一次才会记住。

## 约定

每个习题都是独立 Go module，四个目标一样：

```bash
make run      # 未实现会打印一行错误并返回 1，这是预期的
make check    # 与 expected/ 逐字节比对，通过时打一行结论
make test     # 只做 go vet，检查能不能编译
make answer   # 退路：跑参考实现，输出落 out-answer/（不参与比对）
```

## 判分方式：快照 diff，不给单元测试

参考实现里有几十个单元测试（`01-portstate` 一个文件就有 640 行断言）。这里故意**不给**：测试会把期望行为拆成几十条断言，等于把答案连同判据一起写在题面上。

快照只有一份。diff 出来的每一行都在说「这里不对」，但不说为什么——为什么在 README 的坑列表与对应课文的判据里。

两条使用建议：

- **先让结构性字段全对，再抠措辞。**`cause`/`owner`/`verdict`/`trusted` 这些是逻辑，`evidence`/`reason` 是表达。逻辑对了表达差一点，diff 会红，但你已经学到了；逻辑错而表达对，才是真没懂
- **diff 全绿之后，再读一遍参考实现。**看看它在同样的地方是不是还有一层你没想到的分支（每个 README 的坑列表就是这些分支的清单）

## 不进 CI

这四个习题的 `make check` 在初始状态下必然失败，所以不进 `scripts/check-labs.sh`，也不进 GitHub Actions。CI 只保证 21 个参考实现可跑。

改样本、写实现都不会影响别人的构建——每个习题有自己的 `go.mod` 与 `out/`。

## 想加第五个？

照抄现有四个的结构：

```text
exercises/NN-name/
├── README.md      任务书：输出契约、判据、卡住时看哪
├── go.mod         独立 module
├── model.go       数据结构与 IO（给定）
├── xxx.go         只留目标函数的签名 + 注释里的判据
├── expected/      从参考实现的 out/ 复制
├── samples/       从参考实现复制
└── Makefile       run / check / test / answer / clean
```

三条注意：骨架要能编译（未用到的 import 删掉）；`answer` 的输出写 `out-answer/` 而不是 `out/`；README 里不出现成因名、算法名、阈值数字——那些是答案。
