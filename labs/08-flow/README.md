# 08-flow · 流数据解析与采样误差

第 20–22 课的配套实验。喂进两份录好的样本——sFlow 的报文头样本、NetFlow/IPFIX 的流记录——输出 TopN 与字节/包统计；再来一份真值，按 1:100 / 1:1000 / 1:10000 抽样，把 TopN 的失真量出来。

这个实验有两个落点。

**口径**：sFlow 采的是报文样本，每 N 个包抓一个包头，字节数是「样本长度 × 采样率」，是估算；NetFlow/IPFIX 采的是流的聚合记录，字节数是 exporter 数出来的，是计数。都叫「流」，答案不是一回事。两张表分开出，不合并。

**可见性**：1:1000 采样，一条每秒 500 包的流平均每 2 秒才被抽到一次。TopN 上永远是那条 25000 包/秒的大象，而十条这样的小流能把一条链路压死。实验给一张阈值表，让「最小可观测流速率」变成一个能代入自己规模的数。

## 跑起来

```bash
cd labs/08-flow
make run        # 解析两个源 + 跑一遍采样误差，产物落 out/
make flows      # 只解析样本：段账 + TopN
make sampling   # 只跑采样误差
make try        # 换个模板寿命（3 分钟）再解析，看哪些段变成不可信
make merge      # 演示两个源直接相加的双计错误
make test       # vet + 单元测试
make clean      # 删 out/
```

零外部依赖，不连网、不连设备，样本是手读得了的 JSONL。

## 两个源的口径

| | sFlow | NetFlow / IPFIX |
|---|---|---|
| 采的是什么 | 每 N 个包抓一个包头 | 流收敛后的聚合记录 |
| 字节数怎么来 | 样本长度 × 采样率（**估算**） | exporter 自己数完报上来（**计数**） |
| 谁定采样率 | agent 配置，样本自带 `sampling_rate` | exporter 配置，记录里不带 |
| 误差形状 | 约 ±1/√c，c 是这条流抽到的样本数 | 采样那一段同样有误差，聚合之后不再有 |
| 最适合回答 | 谁在打流量、打什么协议 | 谁和谁通了多少、通了多久 |
| 本实验的 TopN | 4 条 | 5 条 |
| 可信度依据 | 采样率与报文头长度是否齐全 | 模板是否能对上 |

两张表分开出，这是刻意的。`make merge` 把两个源直接相加，你会看到同一批流量在表里成了两行——因为 NetFlow 那边的模板没带 `src_port`，两个源的 key 粒度根本不一致。

## 样本格式

样本模拟的是**应用层语义**，不是真 UDP 字节流：真实报文的 set ID、变量长字段、padding、企业私有字段都省掉了，留下的是解析时必须做决定的那几件事——采样率怎么放大、模板从哪来、模板过期了还认不认。

### `samples/sflow.jsonl`

一行一个 datagram，6 行。datagram 内所有样本属于同一时刻。

```json
{"ts":"2026-05-12T10:00:00Z","agent":"10.0.0.11","seq":9001,"samples":[{"seq":1,"if_index":48,"sampling_rate":1000,"header":{"src_ip":"10.20.0.10","dst_ip":"10.30.9.9","proto":"tcp","src_port":51400,"dst_port":445,"bytes":1514,"tcp_flags":"A"}}]}
```

| 字段 | 含义 |
|---|---|
| `ts` / `agent` / `seq` | 采集时间、设备管理地址、datagram 序号 |
| `if_index` | 采样口。**不用它做 TopN 的 key**，换块业务板就重排 |
| `sampling_rate` | 平均每多少个报文抽一个。`1000` 就是 1:1000，`0` 表示设备没报 |
| `header` | 被抽中的那个报文的头：五元组 + 报文长度 + TCP 标志 |

一个样本代表 `sampling_rate` 个报文，所以估算字节 = `bytes × sampling_rate`，估算包数 = `sampling_rate`。样本里 18 个样本、16 个可信：`seq=9` 的采样率是 0，`seq=15` 的报文头长度是 0，两条都放大不出来，直接丢并计数。

### `samples/netflow.jsonl`

一行一个 export，9 行，按到达顺序录的（加载时会检查时间戳单调，倒序直接报错）。

```json
{"ts":"2026-05-12T10:00:00Z","exporter":"10.0.0.11","seq":1,"sets":[{"template":{"id":256,"fields":["src_ip","dst_ip","proto","octets","packets"]}},{"data":{"template_id":256,"records":[["10.20.0.10","10.30.9.9","tcp",142800000,94320]]}}]}
```

| 字段 | 含义 |
|---|---|
| `ts` / `exporter` / `seq` | 导出时间、exporter 地址、报文序号 |
| `sets[].template` | 模板记录：`id` + `fields` 字段顺序 |
| `sets[].data` | 数据记录：`template_id` + `records`，每条记录是**按模板字段顺序排列的值数组** |
| `records` 里的值 | 位置对齐模板，不是带 key 的对象。真报文里没有 key，只有偏移量 |

值数组是刻意的。对象形式的 `{"octets":8421}` 永远读不错；位置形式才复现真实故障：模板顺序一变，字节数落进包数。

认识的字段只有 7 个：`src_ip`、`dst_ip`、`proto`、`src_port`、`dst_port`、`octets`、`packets`。

### `samples/flows-truth.json`

采样误差实验的真值：一条大象 + 一窝老鼠，加一句 fanout 子句（180 条手写样本没人看得下去）。

| 字段 | 含义 |
|---|---|
| `window_seconds` | 统计窗口，60 秒 |
| `mean_packet_bytes` | 平均包长 1000 字节，用来把包数折成字节与带宽 |
| `flows[]` | 显式流：名字、五元组、`pps`（每秒包数） |
| `fanout` | 同一模板复制 `count` 份，只换源 IP（从 `src_ip_base` 往后数，限同一 /24） |

`pps` 才是关键量，不是带宽。采样按包抽，一条 200 Mbps 的流如果都是 64 字节小包，它的包速率比一条 300 Mbps 的 1514 字节大流还高，更容易被看见。

## 段的可信度怎么判

一个 data set 就是一段。段是判定的最小单位：模板不对，这段里每条记录都不可信，只丢一半没有意义。

| 状态 | 触发条件 | 处理 |
|---|---|---|
| `ok` | 模板在寿命内、字段都认识、长度都对 | 参与统计 |
| `template_missing` | 这个模板 ID 在这个 exporter 上没收到过 | 整段丢弃，标不可信 |
| `template_expired` | 距上次模板刷新的时长超过寿命 | 作废并删除模板，后续段按缺失处理 |
| `length_mismatch` | 某条记录的值个数与模板字段数不符 | 整段丢弃，报出是第几条 |
| `unknown_field` | 模板里有本实验不认识的字段 | 整段丢弃 |
| `field_type` | 值类型不对（比如 `octets` 是 `"不是数字"`） | 整段丢弃 |

模板寿命默认 30 分钟（RFC 7011 建议 3 倍模板刷新周期），可用 `-template-ttl` 改。`make try` 把它挪到 3 分钟：`10.0.0.11 seq 9` 那一段从可信变不可信，覆盖率从 70.6% 掉到 64.7%，合计从 420.5 MB 掉到 358.4 MB。

这两条要一起看：**覆盖率按记录条数算，不按字节算**。没解析就没有字节数，所以「这段不可信」永远给不出「丢了多少字节」。这就是不可信的含义——不知道丢了多少，只能不给数。

## 采样误差怎么算

抽中率、误差、阈值三个式子，都能自己代入：

```text
抽中率 = 1/N
估算字节 = 样本字节 × N
相对标准误差 ≈ 1/√c            c = 这条流抽到的样本数
最小可观测包速率 r_min = k·N/T   k = 窗口内至少采到的样本数，T = 窗口秒数
```

第三条的来历：每秒 r 个包的流，在 1:N 下每秒产出 r/N 个样本，T 秒共 r·T/N 个。令它等于 k，解出 r = k·N/T。代入 N=1000、T=60s、k=1，得 16.7 包/秒，按 1000 字节包长折 133 kbps。

`k=1` 是「看得见」的下限，不是「算得准」的下限：一个样本的估计误差是 ±100%。要相对误差压到 45%，至少 5 个样本；压到 10%，得 100 个。所以表里同时给 k=1 和 k=5 两列。

按这个阈值回看样本：180 条批处理流各 12 包/秒，在 1:1000 下 `r_min = 16.7`，低于阈值，平均每个窗口只有 0.72 个样本。它们照样出现在 Top5 里：`mice-batch-108` 抽到 3 个样本，放大成 3.0 MB，真值只有 720 KB（真值里 180 条同级，`#5` 到 `#184` 全是并列）。低于阈值不等于抽不到，只是抽到的次数不足以撑住排名——今天它是第 5 名，明天它在第 90 名，两个数字都是真的。

## 这个实验故意留的坑

1. **两个源的 TopN 不能相加**。sFlow 是估算，NetFlow 是计数；更要命的是 key 粒度不同：`10.0.0.12` 的模板没带 `src_port`，同一批流量在 sFlow 表里带端口、在 NetFlow 表里不带，合并表上成了两行，各自看起来都很正常。`make merge` 就是演示这件事。
2. **模板 ID 是每个 exporter 自己分配的**。样本里 `10.0.0.11` 和 `10.0.0.12` 都用 300，字段完全不同。只按 ID 缓存（不带 exporter），A 的模板会套到 B 的记录上。
3. **模板重定义后字段顺序变了，长度没变**。`[..., octets, packets]` 改成 `[..., packets, octets]`，把 8421 字节读成 8421 个包、7 个包读成 7 字节，不报错、不越界，报表上看不出异常。代码以最新模板为准（`TestTemplateRedefinitionOrderMatters` 同时验了「按旧模板读会换位」）。
4. **模板寿命是口径，不是常量**。`make try` 一挪过期线，可信段立刻变垃圾段。这个数该由 exporter 的刷新周期和一条模板被 UDP 丢掉的概率共同决定，没有普适值。
5. **采样率配错了，整套数字等比错**。agent 报 1000、实际配的是 4096，所有估算字节都缩成 1/4，TopN 排名完全不变。交叉校验得拿接口计数器的总字节对账（那是 `07-counters` 的活），本实验不做。
6. **采样率 0 不能当 1 用**。`seq=9` 的 rate 是 0，按 1 算会得出「这 1514 字节就是全部流量」，按 0 算是「零流量」，两个都是假的。代码丢样本并计数。
7. **报文头长度 0 的样本也要丢**。`seq=15` 的 `bytes=0`，乘任何采样率还是 0，TopN 上它会被当成一条「不传数据」的流。
8. **±误差是上界估计，不是置信区间**。`1/√c` 假设按包独立抽样。真实 NetFlow 常配「每 N 个包取第 N 个」的确定性采样，遇到周期流量会锁相：误差要么是 0，要么是整倍偏差。本实验只模拟随机抽样。
9. **第一名稳，量不稳**。1:10000 下大象流 139 个样本，估算 1.39 GB、真值 1.50 GB，误差 7.33%。看排名可以说「还是它」；报量不能说「1.39 GB」。
10. **五元组缺字段会静默合并**。`10.0.0.12` 的模板没带 `proto`，TopN 那条流显示 `/any`，tcp 与 udp 被并成一条。口径不一致要在采集侧校验，别等报表出来才发现。
11. **时间戳乱序会让模板年龄算成负数**。加载时直接挡住非单调的 `ts`。真实采集器也不能按 `ts` 重排后再处理——重排会让一份过期模板复活。
12. **聚合之后没有采样率可乘**。NetFlow 记录里的 `octets` 已经是定量，再乘 1/N 就把 420.5 MB 变成 420.5 GB。这个错法在拼装两个源的代码时最容易犯。

| `samples/sflow.jsonl` | 6 个 datagram、18 个报文头样本，含采样率 0 与长度为 0 两条坏样本 |
| `samples/netflow.jsonl` | 9 个 export：模板过期、模板重定义换位、模板缺失、长度不符、双 exporter 同号模板 |
| `samples/flows-truth.json` | 1 条大象 + 3 条明写的老鼠 + 180 条 fanout 老鼠 |
| `out/topn.json` | 解析产物：两个源（含 `make merge` 的合并表）各自的 TopN 与覆盖率 |
| `out/sampling.json` | 模拟产物：每个采样率的逐流真值/估算/排名与阈值 |

产物里 `out/topn.json` 的顶层带一句 `note`：sFlow 的字节数是估算、NetFlow 的是计数，两者不可相加。这句话进产物，下一个拿到 JSON 的人才不会顺手写个 `sum()`。
