# 18-case · 端到端案例回放

第 48 课配套实验。0.3% 丢包那个案例的十步回放：输入一份时间线样本，程序逐步输出「该看什么、看到什么、能不能往下走」，最后给出结论与证据链。

**关键约束：步进逻辑只看样本数据，不许硬编码结论。** 把样本里的网卡计数抹平，结论必须变成「未定位」——这条写进了测试。

零外部依赖，不碰网络。

## 跑起来

```bash
cd labs/18-case
make run          # 十步回放 + 证据链 + 结论
make test         # go vet + go test
make json         # JSON 输出，供脚本消费
make clean        # 删 out/
```

## 样本

`samples/case.json` 一份，字段：

| 字段 | 含义 |
|---|---|
| `app` | 应用 p99（前/后）、CPU、trace 指向 |
| `alarms` | 告警列表（这里是空，故意的） |
| `paths` | 三条探测路径，含包数与丢包率 |
| `switch_ports` | 三台交换机端口计数器（干净） |
| `host_nics` | 三台主机的网卡计数（一台 `rx_fifo_errors` 在涨） |
| `changes` | 同期变更（内核升级并重启） |
| `clock_offsets` | 五个源的时钟偏差（设备偏 41 秒） |

## 十步

```text
 1. 应用 p99 曲线什么形态        210 → 780 ms，3.7 倍，阶跃
 2. 应用自身资源是否异常          CPU 40%，跟着 trace 走
 3. 监控告警有没有东西            0 条（告警为空不等于没问题）
 4. 受影响的机器集中在哪          同机架 A-03
 5. ping 20 个包                  0% 丢包（20 个包撑不起结论）
 6. 发 1000 个包                  0.32% 丢包，只在那一条路径上
 7. 交换机端口计数器              异常 0 个
 8. 主机网卡丢包计数              rx_fifo_errors = 41230
 9. 同期有没有变更                内核升级并重启（ring buffer 回到 256）
10. 时间轴能不能对上              设备偏 41 秒，结论只覆盖窗口起点之后
```

结论落在第 8 步，第 9 步解释根因，第 10 步限定结论的适用边界。

## 这个实验故意留的坑

1. **第 5 步的样本是「恰好 0% 丢包」**。0.3% 丢包下发 20 个包，94.2% 的概率是全通——样本里这个结果是运气，不是结论。真实排查里最容易在这步停下。
2. **第 7 步全绿不等于链路好**。样本里的交换机计数器干净，但丢包真实存在——因为丢在主机网卡上，交换机根本不知道。
3. **第 9 步的因果是事后认定的**。「内核升级」与「ring buffer 变小」之间是相关性，不是日志里的直接证据。真实复盘需要 `ethtool -g` 的历史快照，样本里没有。
4. **时钟偏差只影响第 10 步的判断**。如果业务侧补偿了偏移，这个数会被掩盖。
5. **十步是理想路径**。真实案例里有两次回头：第 6 步之前怀疑过 ECMP（第 12 课），第 7 步之后差点转去查光纤。
