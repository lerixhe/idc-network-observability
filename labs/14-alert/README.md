# 14-alert · 告警收敛与父子抑制

第 38、39、40 课的配套实验。一个 module，三段能力，回答的是同一个问题：**这次故障到底有几件事**。

| | 父子抑制 | 退化关联 | 规则对比 |
|---|---|---|---|
| 回答 | 哪些告警是那条根因的症状 | 拓扑查不到父时怎么办 | 阈值 / 持续时长 / 变化率各报了什么 |
| 输入 | 告警流 + 影响面树 | 同一份告警，对象不在树里 | 带真故障窗的时间序列 |
| 输出 | 抑制决策 + 收敛比 + 误伤 | 时间窗关联结果 + 误伤 | 命中 / 及时 / 误报 / 漏报 |

一次 Spine 板卡重启，87 条告警。树上一看，只有一条是根因。剩下 86 条里 85 条该压，1 条是另一件事被误压了——那一条也得说清楚。

## 跑起来

```bash
cd labs/14-alert
make run        # 四段全跑，结果打到终端，产物落 out/
make suppress   # 只跑主剧本：板卡重启的 87 条
make degrade    # 只跑血缘缺失与反例两段
make rules      # 只跑三类规则对比
make try        # 「父必须更早」从 5 秒拉到 60 秒，看抑制怎么整个失效
make demo       # README 引用的那份输出：全套 + 三套参数对照
make test       # vet + 单元测试
make clean      # 删 out/
```

零第三方依赖，不连网、不连设备，样本是手读得了的 JSON/JSONL。

## 一、抑制的五道闸

父子抑制听着简单：父在，子不报。真写下去，五道闸少一道就出事。

| # | 闸 | 判据 | 少了它会怎样 |
|---|---|---|---|
| 1 | 血缘 | 父对象必须是子对象的严格祖先 | 拿 A 机的告警压 B 机 |
| 2 | 方向 | 只允许祖先压后代，后代永远不压祖先 | 端口 down 把设备重启压掉 |
| 3 | 时间 | 父告警必须比子告警早出现 `-suppress-lag`（默认 5s） | 晚到的后果被当成原因 |
| 4 | 类型 | 父的 class 必须能解释子的 class | 拿拥塞压重启 |
| 5 | 同层 | 兄弟与同层之间互不压制 | 两个独立故障并成一个 |

第 4 道闸是一张写死的表，`suppress.go` 里的 `explainTable`：

| 父 class | 能解释 |
|---|---|
| `device_reset` | `port_down`、`link_flap`、`probe_down`、`host_down`、`svc_down`、`packet_loss`、`latency_high` |
| `port_down` | `link_flap`、`probe_down`、`host_down`、`svc_down`、`packet_loss`、`latency_high` |
| `host_down` | `svc_down`、`probe_down` |
| `congestion` / `cpu_high` | `latency_high`、`packet_loss` |
| `link_flap` | `packet_loss`、`latency_high` |

表里没有的对，一律不压，宁可多报一条。`device_reset` 压不住 `device_reset`——两台设备同时重启是两件事，不是一件。

第 3 道闸就是第 38 课那条「父告警自己成立之前，不许压制任何子告警」。告警系统里父通常有 `pending` 与 `firing` 两态，这个实验把两态压成一条时间闸：父出现得比子早至少 `-suppress-lag` 秒，才算站住了。

这个参数是个旋钮。拧到 60 秒，抑制整个失效：

```text
$ make try      # -suppress-lag 60s
原始告警 87 条 → 独立投递 87 条：收敛比 1.00:1，抑制率 0.0%
  压掉 0 条 = 净收敛 0（父消失后自行恢复，不补发）+ 补发 0（父没了子还活着）
```

一条都压不住。因为下挂告警全在根因后 50 秒内冒出来，60 秒的闸把它们全放行了。**抑制系统失效的时候不报错，只是收敛比悄悄变成 1.00:1。**

### 挑哪个祖当当父

`bestAncestorAt` 在活跃的祖先里挑**最早的那条**，不是最近的那条。

最近的父是「直接原因」，最早的那条是「根因」。压制链要能回答「为什么这条不该报」，答案必须是根因；拿后果当父，报告里就会出现「A 被 B 压，B 自己也被 C 压」这种查到一半断掉的链。样本里 85 条全挂在 `a-0001` 名下，就是这个选择的结果。

## 二、父消失之后，子必须能回来

抑制最危险的不是压错，是**压住了不松手**。告警可以晚到，不能不来。

回放按事件时刻推进。每来一条告警或一条恢复，活跃集变一次，就重算一次「现在有没有父」。三条判定：

| 情形 | 处置 | 样本里的条数 |
|---|---|---|
| 父消失后子仍在 firing，超出 `-resolve-grace`（默认 120s） | **补发** | 3 |
| 父消失后子很快也恢复，落在宽限内 | 不补发（同一件事的尾巴） | 79 |
| 子先于父恢复，父还在的时候自己就没了 | 不补发 | 3 |

82 条净收敛是后两行之和。它们省掉的是一次投递，不是一条告警——区别在复盘时要说得清。

宽限期是必须的。去掉它，父恢复的那一瞬间，79 条子告警会同时弹出来——收敛比白算。宽限拉得太长，同一件事的尾巴被吞掉：

```text
$ make demo 里的对照二   # -resolve-grace 600s
原始告警 87 条 → 独立投递 4 条：收敛比 21.75:1，抑制率 95.4%
  压掉 85 条 = 净收敛 83（父消失后自行恢复，不补发）+ 补发 2（父没了子还活着）
```

收敛比从 17.40 涨到 21.75。代价是三条该补发的变成两条——数字变漂亮了，代价藏在下面那一行。

## 三、收敛比怎么算

```text
收敛比 = N / M
        N = 原始告警条数
        M = 抑制后需要独立投递的条数
          = 未被压掉的 + 被压但父消失后仍 firing、必须补发的

抑制率 = (N - M) / N
净收敛 = N - M
压掉数 = 净收敛 + 补发
```

主剧本代入：

```text
N = 87
压掉 = 85（净收敛 82 + 补发 3）
M = 87 - 82 = 5
收敛比 = 87 / 5 = 17.40:1
抑制率 = (87 - 5) / 87 = 94.3%
```

血缘缺失剧本代入：

```text
N = 22，压掉 17（净收敛 17 + 补发 0）
M = 5
收敛比 = 22 / 5 = 4.40:1
抑制率 = 77.3%
```

**收敛比不能单独看。** 反例剧本里全贪心口径的收敛比是 20.00:1，比严格口径的 6.67:1 漂亮三倍，代价是把真根因也压掉了。所以每次都要连着误伤数一起看。

## 四、血缘缺失：时间窗关联与它的误伤

拓扑里查不到父，有三种情况，样本里都埋了：

| 情况 | 标记 | 样本 |
|---|---|---|
| 对象完全不在台账里 | `object_unknown` | `acc-a3f-77:Eth1/2` 等 8 条 |
| 对象在，但节点没有父（截断的拓扑） | `no_ancestor` | `device:acc-a3f-88` 1 条 |

退化路径只有一条规则：往回 `-degrade-window`（默认 60s）找一条**更早、类型能解释、严重度不低于自己、对象已知**的告警，当成疑似父。

四个约束都是硬的。最不能松的是「类型能解释」：松了它，退化路径就变成「一分钟内谁红得早谁当爹」。样本里 `device:acc-a3f-88` 自己的重启告警，时间上离 `spine-02` 的重启只有 35 秒，但它压不住对方也不被对方压——`device_reset` 解释不了 `device_reset`：

```text
no_ancestor     1 条（时间窗压掉 0 条）
```

「对象已知」这一条也不能松。两个都查不到对象的告警互相压，等于拿未知压未知，压完谁也说不清为什么——`TestUnknownObjectsDoNotSuppressEachOther` 钉住这条。

退化路径的收益是能接住那 5 条本该被压的子告警，代价是 1 条误伤：

```text
[误伤] s-0015   acc-a3f-77:Eth1/2   truth=independent 被 s-0001 靠时间窗压掉
```

那台交换机的 2 口是自己坏的，跟 `spine-02` 重启没关系。时间窗分不出来——**没有任何算法能分出来**，只能说清它是猜的，并且带上 `degraded: true`。

窗口收到 15 秒，误伤没了，但关联也大批失效：

```text
$ make demo 里的对照一   # -degrade-window 15s
原始告警 22 条 → 独立投递 7 条：收敛比 3.14:1，抑制率 68.2%
  血缘缺失 9 条；其中走时间窗关联压掉 3 条
  误伤 0 条
```

5 条变 3 条，误伤 1 条变 0 条。这就是这个参数的全部权衡：**误伤和漏压是同一个旋钮的两头。**

### 反例：抑制太狠，把真父告警也压了

`samples/alerts-overreach.jsonl` 是专门为这个写的。剧本：`site:room3` 的出口拥塞比 `spine-01` 的板卡重启**早 17 秒**冒出来，拓扑上它确实是祖先。

三套口径跑同一份告警，只差拆掉哪道闸：

| 口径 | 投递 | 收敛比 | 误伤 | 被压掉的真根因 |
|---|---|---|---|---|
| 严格（默认） | 3 | 6.67:1 | 0 | - |
| 只关时间闸（lag=0） | 3 | 6.67:1 | 0 | - |
| 全贪心（lag=0 且不查类型） | 1 | 20.00:1 | 2 | `o-0002`（root）、`o-0019`（independent） |

只关时间闸那一档和严格口径一模一样。**真正拦住真根因的是「父的类型必须能解释子」。** 时间闸在这一档上没起作用；拆掉类型闸，拥塞告警立刻把重启告警压掉，连带 17 条症状全挂在一条无关的拥塞下面。

那 17 条症状还是会被压——它们确实该压。但报告里「压得最多的是 o-0001」这句话会把人带到错误的排障方向上。

## 五、三类规则：同一批数据，三种回答

| 规则 | 判据 | 擅长 | 死穴 |
|---|---|---|---|
| `threshold` | 值 ≥ 85 就命中 | 阶跃、突发 | 单点尖刺必误报；漂移永远够不着 |
| `sustained` | 值 ≥ 85 且连续撑住 180s | 持续过载 | 锯齿（每段都撑不满）；响应天然晚 180s |
| `rate` | 相邻两点斜率 ≥ 0.5/秒 | 阶跃，比阈值早 | 采集中断时完全瞎；缓慢漂移也够不着 |

三条规则在五条序列上的成绩，就是上面那第四段输出。挑三条读：

**漂移序列**（`tor-a3f-01:Ethernet1/48` 丢包率 0.1% → 3.0%，24 分钟）：三条规则 `hits=0 / miss=1`，全漏。漂移是静态阈值的死穴——它每一刻都没越线，二十多分钟爬过去，人反应过来时已经跑了二十分钟。这是第 39 课要讲的基线问题。

**尖刺序列**（`spine-01:cpu_util_pct` 一个采样点 94，前后都是 40）：阈值规则 1 次误报，变化率规则 1 次误报，持续时长规则 0 次命中——它是对的。这就是尖刺和真故障的区别，也是持续时长规则唯一的价值。

**断点序列**（`tor-a3f-04:Ethernet1/1` 240 秒后采集断了 5 个点，恢复时已经 95）：阈值和持续时长都命中了，变化率规则 `hits=0 / miss=1`——它完全没看见。因为代码拒绝跨断点算斜率（相邻间隔 > `-max-gap` 90s 就跳过）。把闸放开，它就能「算出」一个斜率：

```text
$ make demo 里的对照三   # -max-gap 400s -rate 0.3
  rule       hits   on     fa     miss
  rate       12     8      4      1
```

漏报从 2 降到 1。这个斜率是真跨了 300 秒算出来的，与中间到底发生什么无关。

### 参数是抄的

样本里三条规则共用一套参数：阈值 85、时长 180 秒、斜率 0.5/秒，套在 Mbps、百分比、pps 三种量纲上。

这是生产上最常见的错，也是刻意的。85 这个数对丢包率序列没有意义——丢包率爬到 3% 已经该报警了，但 85 的阈值一辈子都够不着。**一套参数套所有指标，等于只对一种指标负责。** 按序列配参数是第 39 课的事，本实验不做。

## 样本格式

### `samples/tree.json`

影响面树。**不是物理拓扑**——设备挂在「上游端口」下，表达的是「那个口坏了会影响这台设备」。

```json
{
  "id": "port:spine-01:Ethernet1/1",
  "kind": "port",
  "parent": "device:spine-01",
  "name": "spine-01:Ethernet1/1",
  "aliases": ["SPINE-01:Eth1/1", "spine-01:ethernet1/1"]
}
```

| 字段 | 含义 |
|---|---|
| `id` | 唯一标识，`kind:name` 形式。端口带设备前缀 `port:spine-01:Ethernet1/1` |
| `kind` | `site` / `device` / `port` / `host` / `service`，五层 |
| `parent` | 上一层的 ID。空串表示这是树根或孤岛 |
| `name` | 展示名，报告里打印这个 |
| `aliases` | 告警里可能的其他写法。**唯一入口**，翻不出来就走退化路径 |

六台设备、23 个端口、28 台主机、28 个服务，87 个节点。`acc-a3f-88` 故意没有父（截断的拓扑），`acc-a3f-77` 故意不在树里（幽灵设备）。

从 `10-topology` 的输出推这棵树，四条边各管一段：

```text
cmdb.json 的 devices[].ports     →  device:X  →  port:X:P
out/links.jsonl 的 physical 链路  →  port:A:P  →  device:B     （影响面父边）
ARP / FDB / DHCP 快照            →  port:X:P  →  host:IP
服务清单                          →  host:IP   →  service:name@IP
```

这个实验把四步合并成了一份手写文件，让「抑制」本身显形。真接 `10-topology` 的时候，这四步里每一步都会引进自己的错——别名缺一条、链路单侧、LAG 没对齐。

### `samples/alerts.jsonl`

87 行，一行一条告警。四源共用一种信封，每个源负责它说得清的那类：

```json
{"id":"a-0002","ts":"2026-05-12T10:14:05Z","resolve_ts":"2026-05-12T10:15:26Z",
 "source":"trap","obj":"SPINE-01:Eth1/1","class":"port_down",
 "severity":"critical","summary":"Ethernet1/1 link down，光模块收无光","truth":"child"}
```

| 字段 | 含义 |
|---|---|
| `ts` / `resolve_ts` | 发生与恢复。`resolve_ts` 空表示到样本结束还没恢复 |
| `source` | `trap` / `syslog` / `probe` / `counter` |
| `obj` | 对象写法，可以写别名。**必须定位到唯一节点**，裸端口名（`Ethernet1/1` 在多台设备下都有）会在建树时撞车 |
| `class` | 告警类型，决定第 4 道闸 |
| `severity` | `critical` / `major` / `warning`，退化路径用它比高低 |
| `truth` | 样本给的真值：`root` / `child` / `independent`。**只用于算误伤，抑制逻辑一个字都不读** |

`obj` 故意混了三种写法：`SPINE-01:Eth1/1`、`spine-01:Ethernet1/2`、`spine-01:ethernet1/3`，还有 `port:spine-01:Ethernet1/9` 这种直接写 ID 的。四种都要落到同一个节点上。

另外两份剧本：

| 文件 | 条数 | 演什么 |
|---|---|---|
| `alerts-sparse.jsonl` | 22 | 血缘缺失。`object_unknown` 8 条、`no_ancestor` 1 条；另有 3 条离窗口太远、1 条是另一个站点的根因，都正常放出 |
| `alerts-overreach.jsonl` | 20 | 反例。站点级拥塞比板卡重启早 17 秒，贪心口径会把它当真父 |

### `samples/metrics.jsonl`

5 行，一行一条序列。点写成 `[秒, 值]` 两列数组。

```json
{"series":"spine-01:Ethernet1/1:rx_bps","unit":"Mbps","start":"2026-05-12T10:00:00Z",
 "points":[[0,62],[30,62],...],"faults":[[300,720]]}
```

| 字段 | 含义 |
|---|---|
| `points` | 相对 `start` 的秒数与值，必须严格递增 |
| `faults` | 真故障窗，同样是相对秒。**规则本身看不到它**，只用来算误报漏报 |

五条序列各埋一种形态：阶跃（`rx_bps`）、漂移（`pkt_loss_pct`）、尖刺（`cpu_util_pct`）、锯齿（`queue_drop_pps`）、断点+阶跃（`rx_error_pps`）。

## 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `-suppress-lag` | 5s | 父告警必须比子告警早出现多久 |
| `-degrade-window` | 60s | 血缘缺失时，往回找疑似父的时间窗 |
| `-resolve-grace` | 120s | 父消失后子告警也恢复的宽限，窗内不补发 |
| `-explain-required` | true | 是否要求父的类型能解释子的类型 |
| `-threshold` | 85 | 阈值规则的过线值 |
| `-sustain` | 180s | 持续时长规则的时长下限 |
| `-rate` | 0.5 | 变化率规则的斜率上限（单位/秒） |
| `-max-gap` | 90s | 相邻采样点的最大合法间隔，超了算采集中断 |
| `-mode` | all | `all` / `suppress` / `degrade` / `rules` |
| `-out` | out | 输出目录，给空串则不落盘 |

前五个是抑制口径，后四个是规则口径。九个都是策略，不是常量——换一档设备档位就该重调。

## 这个实验故意留的坑

1. **`-suppress-lag` 拧大，整个抑制静默失效**。拧到 60 秒，87 条一条都压不住，收敛比 1.00:1，程序一声不响。这个参数最好配上「压掉数 < 某个下限就告警」的看门狗。
2. **收敛比越漂亮越要先看误伤**。全贪心口径 20.00:1，严格口径 6.67:1。差距全在「它把不该压的也压了」。
3. **`device_reset` 压不住 `device_reset`**。两台设备同时重启是两件事。样本里 `spine-02` 的重启就是这么保住自己的——它挂在 `spine-01` 的端口下，类型闸救了它。
4. **误伤是结构性的，不是 bug**。`tor-a3f-03:Ethernet1/7` 那个口自己坏了，拓扑上它确实挂在 `spine-01` 下面，`device_reset` 确实能解释 `port_down`。代码判不出来，只能记下来。
5. **退化路径的误伤换不来零误伤**。窗口从 60 秒收到 15 秒，误伤归零，同时 5 条关联掉到 3 条。压得太松和压得太紧是同一个旋钮。
6. **「对象已知」这道约束是防倒退的**。两个都查不到对象的告警互压，等于拿未知压未知——样本里 `acc-a3f-77` 自己发的告警不许互相关联。
7. **挑最早的祖先，不是最近的**。压制链要回答「为什么这条不该报」，答案得是根因。挑最近的会把报告变成「A 被 B 压，B 自己也被 C 压」的断链。
8. **宽限期是收敛比的水分**。拉到 600 秒，收敛比从 17.40 涨到 21.75，补发从 3 条掉到 2 条。同一件事的尾巴被吞掉了，数字变好看，事故复盘时会缺一块。
9. **漂移类故障三条规则全漏**。丢包率 24 分钟从 0.1% 爬到 3%，阈值、持续时长、变化率各自命中 0 段。缺的那一层是基线，第 39 课。
10. **变化率规则在采集中断处彻底瞎**。样本里 `tor-a3f-04:Ethernet1/1` 断了 5 个点，真故障就发生在断口里，`rate` 的 `miss=1`。把 `-max-gap` 放开它就能命中，命中一个跨了 300 秒的假斜率。
11. **锯齿让阈值规则狂报**。`queue_drop_pps` 在 76 和 92 之间来回，阈值规则命中 9 段，其中 3 段在故障窗之外。持续时长规则一次都不命中——它是对的，但它分不清「锯齿」和「尖刺」。
12. **一套参数套所有指标**。阈值 85 对 Mbps、百分比、pps 一视同仁，对丢包率序列没有任何意义。
13. **事件时间回放假设时间戳可信**。设备时钟差 40 秒，第 3 道闸（父必须更早）就会把真正的父排到子后面去，然后整条链断掉。这件事得先把时间对齐（第 46 课），抑制救不了。
14. **告警恢复靠样本里给的 `resolve_ts`**。真实系统的恢复来自 trap、轮询对账、或者超时兜底，三条路的时间精度差很多。这里的回放假设恢复时间是准的。
15. **抑制链只截断环，不拒收环**。堆叠与跨设备聚合能造出环（第 38 课点名过），`Ancestors` 遇到回边就停下，不会挂死，但建树时不做环检测——环上的抑制会互相吞掉，最后一条都不响，而树看着是好的。要拒收，在 `NewObjectTree` 里加一次拓扑排序。
16. **服务层节点必须带实例标识**。样本里写成 `order-api@10.20.99.11`。去掉 `@ip`，三台主机上的 `order-api` 会撞进同一个节点，抑制关系当场乱掉。
