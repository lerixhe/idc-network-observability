# 05-int-sim · INT 逐跳数据还原

第 13 课的配套实验。给一份录好的 INT 元数据，做两件事：**把端到端时延拆到每一跳**，以及**只有一部分跳有数据时，说清哪一段是盲区**。

端到端 RTT 涨 2 ms，是哪一跳涨的？端到端测量答不了这个问题——它只有一个数。INT 让每个节点往包头写入口时间戳、出口时间戳、队列深度、端口，于是这个问题有答案，前提是每一跳都吐数据。

## 跑起来

```bash
cd labs/05-int-sim
make run     # 只看 INT 元数据，不给真值，跟生产环境一样
make test    # vet + 单元测试
make demo    # 带真值对账（README 里的样张就是它）
make try     # 只看部分覆盖那条：盲区段吸收了多少
make clean   # 删 out/
```

零外部依赖，不发包、不连设备。

## 时延分解怎么算

三个量，口径完全不同，混起来用就错了：

| 量 | 算式 | 单位 | 可信度 |
|---|---|---|---|
| 驻留 `resident` | 出口时间戳 − 入口时间戳 | ns → 打印 µs | **精确**。同一台设备的两个时间戳，时钟偏移自动抵消 |
| 排队 `queue` | 队列深度 × 8 ÷ 出口速率 × 10⁹ | ns | **估算**。深度是采样时刻的瞬时值，与本包的等待不是一回事 |
| 处理 `forward` | 驻留 − 排队 | ns | 减出来的。包含包头解析、查表、交换结构、自身序列化 |
| 传播 `prop` | 台账长度 × 5 ns/m | ns | 估算。光纤里约 2×10⁸ m/s，即 5 µs/km |
| 端到端 `e2e` | 末跳出口 − 首跳入口 | ns → 打印 µs | **含误差**。跨了时钟域，误差等于首末跳的偏移差 |

代入一遍，`spine-01` 那一跳：

```text
队列深度 39 600 000 字节，出口速率 100 Gbit/s
排队 = 39 600 000 × 8 ÷ 100 000 000 000 × 10⁹
     = 316 800 000 bit ÷ 100 000 000 000 bit/s
     = 3.168 ms = 3 168 000 ns = 3168.0 µs

驻留 = 3 202 100 ns
处理 = 3 202 100 − 3 168 000 = 34 100 ns = 34.1 µs
```

再看 `tor-a3f-01`（25 Gbit/s，队列 4144 字节）：

```text
排队 = 4144 × 8 ÷ 25 000 000 000 × 10⁹ = 1326 ns = 1.3 µs
处理 = 3100 − 1326 = 1774 ns = 1.8 µs
```

两端加起来才是端到端。这条恒等式是所有结论的地基：

```text
端到端(测量) = 驻留合计 + 链路传播 + 盲区驻留 + (末跳时钟偏移 − 首跳时钟偏移)

移项：
盲区驻留 = 端到端(测量) − 驻留合计 − 链路传播 − 时钟偏移差
        = 差额 − 传播 ± 时钟误差
```

全跳有数据时盲区驻留应当为 0，样本里算出 0.3 µs，落在 ±2 µs（两个 ptp 域）之内，判「无盲区」。

## 部分覆盖时输出什么

只有一部分跳有数据时，能说的只有三句：

1. **已归因多少**：驻留合计 ÷ 端到端。样本里 394/5610 = 7.0%。
2. **差额落在哪个段**：差额减掉传播，就是盲区跳的驻留之和。样本里 5126 µs。
3. **这个数有多准**：区间宽度 = 首末跳时钟精度之和。`ptp + ntp` = 1 µs + 1 ms，所以区间是 [4125.1, 6127.1]。

不能说的是「哪一跳慢」。盲区段里有 2 跳，差额是两跳之和，没有任何数据能拆开它。所以输出里那句话是固定的：`2 跳都在盲区里，分不清是哪一跳排队`。

段的定义：**上一个有数据的跳的出口 → 下一个有数据的跳的入口**。段内包含中间那些盲区跳的驻留，加上中间的链路传播。

段只有一段时，差额可以整段分下去。有两段以上就不行了——差额是几段之和，代码里 `Allocatable` 直接置 false，只给总量。

## 样本格式

### `samples/traces.json`

一份报文穿过六跳的元数据。`int_enabled=false` 的跳没有时间戳与队列深度，字段直接不出现。

| 字段 | 含义 |
|---|---|
| `index` | 跳号，从 1 连续。跳号断了就报错，别猜 |
| `device` / `role` | 设备名与角色（leaf / spine / border） |
| `ingress_port` / `egress_port` | 进出端口 |
| `int_enabled` | `false` = 这一跳不吐 INT。老设备、没开、采样丢了，在数据里长得一样 |
| `clock_domain` | `ptp` / `ntp` / `free-run`，决定这一跳时间戳的精度上界 |
| `link_length_m` | **进这一跳的链路长度，来自台账，不是 INT 字段**。没有它，差额里分不开传播与排队 |
| `egress_bps` | 出口速率，排队估算的除数。写错一个数量级，排队就错一个数量级 |
| `ingress_ts_ns` / `egress_ts_ns` | 设备本地时钟的纳秒时间戳。**设备之间不对齐** |
| `queue_depth_bytes` / `queue_limit_bytes` | 出队列当前占用与容量。深度超过容量直接报错 |

时钟精度口径（`clock_domain` → 上界）：`ptp` ±1 µs，`ntp` ±1 ms，`free-run` ±10 ms。这张表是策略不是常量，换时间源就得改。

### `samples/truth.json`

仿真台架的真值，生产环境拿不到，只在 `make demo` 里用来对账。里面有每跳的 `link_prop_ns`、`queue_ns`、`forward_ns`、`resident_ns`，以及每台设备的 `clock_offsets_ns`——看完就知道那些「负时延」是怎么来的。

### `out/hop-delays.jsonl`

一行一跳，进时序库用：

```json
{"trace_id":"t-partial","hop":{"index":3,"device":"dci-border-01","role":"border","ingress_port":"Ethernet1/48","egress_port":"Ethernet1/1","clock_domain":"ntp","has_data":false,"resident_ns":0,"queue_ns":0,"forward_ns":0,"queue_depth_bytes":0,"queue_limit_bytes":0,"egress_bps":100000000000,"link_prop_ns":30000,"attribution":"blind"}}
```

### `out/decomposition.json`

一条 trace 一段汇总：端到端、误差上界、已归因、差额、盲区区间、盲区跳数。

## 这个实验故意留的坑

1. **跨设备时间戳相减会出负时延**。样本里 `-1968.5 µs` 不是物理，是 `spine-11` 与 `dci-border-02` 的时钟差了 2 ms。所以 INT 的每一个「时延」字段都只信同跳内的差值。这条坑在真实工具里最贵：数字有、图有、结论全错。
2. **队列深度是采样时刻的瞬时值**。`t-partial` 的 `spine-01` 那条：深度算出排队 323.2 µs，但驻留只有 322.1 µs，减出负的处理时延。代码按驻留封顶并把矛盾打在表下面。真实原因还有一层：深度是整个出队列的占用，本包前面可能排着别人的包。
3. **队列深度不含本包自己的序列化时间**。1500 字节的帧在 100G 口上是 0.12 µs，25G 口上 0.48 µs。大包或者多级队列时这个差会进「处理时延」，看起来像设备变慢了。
4. **共享缓存会打脸**。深度只是出队列占用，交换机是共享缓存：别的队列在丢包、在挤占，你的等待时间和自己的队列深度不再是线性关系。`queue = depth × 8 ÷ rate` 是一条近似曲线，不是物理定律。
5. **链路长度来自台账，台账错了会算进盲区**。传播按 5 ns/m 估，多记 1 km 就多算 5 µs，全部落进「盲区驻留」。`09-cmdb` 那个实验的脏台账在这里会被放大成错误的归因。
6. **端点时钟精度决定区间宽度**。`t-partial` 一头 ptp 一头 ntp，区间宽度 2 ms：够说「问题在这两跳里」，不够说「是 dci-border-01」。想让结论硬，先把时间同步做上去。
7. **首末跳没有 INT，端到端就不可测**。代码直接报错，不猜。要靠主机侧时间戳兜底（第 46 课）。
8. **「这一跳没数据」有两种原因，样本里长得一样**：设备不支持 INT（结构性缺失），和 INT 采样把这一份丢了（概率性缺失）。前者多采几次也没用，后者多采几次能补齐。实验里 `int_enabled=false` 只表示前者。
9. **多个盲区段时差额不可分**。代码把 `Allocatable` 置 false，只给总量。硬按段数平均分，是最常见的那种「看起来有结论」的错。
10. **`bps` 与 `Bps` 差 8 倍**。`depth × 8 ÷ rate` 里少乘 8，排队时延就小一个数量级，而且所有跳一起小，看起来还挺自洽。
11. **48 位纳秒时间戳 78 小时回绕一次**。2⁴⁸ ns = 281 475 s ≈ 78.2 h。样本时间戳是 64 位所以没埋这个坑，真实 INT shim 里见过 32 位的，那就 4.29 秒一轮。
