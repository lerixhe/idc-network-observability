# 20-probe-security · 下发签名与速率自限

第 32、52 课配套实验。三件与「探针会不会闯祸」有关的事：任务下发的签名、两级令牌桶、配置错误的失控演示。

零外部依赖（只用标准库 `crypto/hmac`），不连网，不发真实包。

## 跑起来

```bash
cd labs/20-probe-security
make run     # 三个场景
make test    # go vet + go test
make clean   # 删 out/
```

`make run` 的输出分三段，见下。

## 场景一：两级令牌桶

1300 个探针，每个每秒想探 10 个目标，共 250 个目标：

```text
单目标配额 10 pps、全局配额 8000 pps
需求       39,000 次/3 秒 = 13,000 pps
放行       7,500 次（19.2%）→ 2,500 pps
单目标拦下 31,500 次（80.8%）
全局拦下   0 次
```

单目标先拦，全局一个都没触发——这是刻意设计的顺序。反过来的话，全局桶会先被占满，单目标桶就永远看不到自己的配额。

**一个容易写错的细节**：全局拒绝时，单目标已经扣掉的令牌必须退回。不退回的话，一个被全局卡住的探针会把自己的单目标桶耗光，等全局恢复时它仍然是满配额用不了。

## 场景二：配置错误失控

```text
正常      1200 探针 × 8 目标 ÷ 5 秒 = 1,920 pps / 1.9 Mbps
配错     1200 探针 × 82,000 目标 ÷ 5 秒 = 19,680,000 pps / 19.8 Gbps
2×10G 出口占比 99%
```

数字对上第 52 课那次事故：某机房出口被自己的探针打满。

程序同时演示了探针侧的硬闸门：一次拉取超过 500 个目标就拒绝执行并上报。这道闸门在，事故就不会发生——第 52 课那次没拦住，是因为它写在任务下载之后。

## 场景三：签名与轮换

```text
✓ 正常任务     → 通过
✓ 篡改目标     → 签名不匹配
✓ 已过期       → 签名已过期
✓ 重放         → 重放：nonce 已用过
✓ 上一版密钥   → 通过（共存期）
```

签名原文是固定顺序的字段串（`v1&task=…&target=…&period=…&deadline=…&nonce=…`），不含签名本身。轮换期两把密钥都验得过，新签发一律用当前密钥。

## 这个实验故意留的坑

1. **nonce 表只在进程内**。探针重启后 nonce 表清空，重放窗口重新打开。真实系统要把用过的 nonce 落到本地磁盘或用一个单调计数器替代。
2. **过期判断只看 `Deadline`**。没有校验 `Deadline` 是否「太远」（攻击者签一个 10 年后的截止时间，密钥泄露后长期可用）。补法是加一个最大有效期。
3. **单目标桶永不淘汰**。目标列表大的时候内存会涨；真实实现要有 LRU。
4. **令牌桶用浮点**。长时间运行会有微小误差，规模大时要用整数（微令牌）表示。
5. **「全局拒绝时退还单目标令牌」这条没有并发保护**。单 goroutine 是对的，多探针共享限流器时要加锁。
