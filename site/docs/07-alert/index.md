## 这一篇解决什么

给数据立口径，再把口径翻译成规则。

同一个「丢包率」有三种算法：探测失败率、计数器丢弃比、误码与错包推算，三个数能差一个数量级。两边都「对」，对不上账就是平台的问题。「可用率」也一样要分层定清：设备可用率（管理面可达时段）、端口可用率（`operStatus` 为 up 的时长）、链路可用率（两端都 up 且无抖动），三个分母不同，报表上的数字就差很多。

口径之后是告警。上线第一周每天 800 条，第二周就没人看了——**值班体验也是功能需求**。这一篇的终局不是「规则写对」，是「剩下的告警条条有人管」。

38 课接第二部分：端口 down 是父告警，它下面挂着「这批机器服务不可达」「这条链路时延上升」一堆子告警。抑制逻辑写错，运维一晚上收到三千条。父子关系怎么建（依赖拓扑）、抑制方向（父压制子，不反向）、父子关系缺失时怎么退化成时间窗关联，是这一课的三件事。

40 课讲五种形态——阶跃、漂移、尖刺、锯齿、缺失，各自指向什么。微突发单独讲：队列 200ms 内打满又恢复，60 秒采样的计数器看不出变化，但 p99 翻倍。

## 读完你应该能

- 给每个指标写下定义式与分母，让两个人算出来是同一个数
- 判断一批标签会不会把时序库撑爆，并给出控法
- 把 800 条告警收敛到 3 条，且说清每一条为什么还在
- 解释静态阈值在哪些场景下必然误报，以及动态基线为什么也不是万能
- 从曲线形态直接指出下一步查哪儿
