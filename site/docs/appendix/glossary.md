## 网络与设备

| 术语 | 一句话 | 课 |
|---|---|---|
| IDC | 数据中心。本书指以通用服务器与以太网为主体的传统机房 | 00 |
| TOR | Top of Rack，机柜顶上的接入交换机 | 01 |
| Spine | 骨干层交换机，连接大量 TOR | 01 |
| 汇聚层 | TOR 与 Spine 之间的中间层，大机房才单独存在 | 01 |
| 上行链路 | 交换机到上一层的链路，通常 2–4 条，做聚合或 ECMP | 01 |
| LAG / 链路聚合 | 多条物理链路绑成一个逻辑口，成员口与逻辑口状态是两回事 | 25 |
| 堆叠 | 多台交换机当一台用，一条逻辑链路的两端可能在不同设备上 | 25 |
| ECMP | 等价多路径，按五元组哈希把流量分摊到多条路径 | 12 |
| 五元组 | 源 IP、目的 IP、源端口、目的端口、协议，哈希的输入 | 12 |
| VLAN | 二层逻辑隔离，物理通而逻辑不通的典型来源 | 25 |
| VXLAN | 三层网络上叠二层，MTU 与隧道端点是常见故障点 | 25 |
| 单向链路 | 一根纤断了、另一根还活着：本端 up 对端 down，或两端收光差极大 | 04 |
| flapping | 端口在窗口内反复 up/down，业务不中断但反复收敛 | 05 |
| DDM / DOM | 光模块的数字诊断监控，五个参量：温度、电压、偏置电流、收光、发光 | 06 |
| 收光 / 发光 | 模块接收与发射的光功率，单位 dBm，负得越多越弱 | 06 |
| 偏置电流 | 激光器的工作电流，老化时上升，与收光下降同时出现才判定模块问题 | 06 |
| FCS / CRC 错误 | 帧校验失败，说明包进来的时候就坏了，不是被队列丢的 | 18 |
| 符号错误 | 物理编码层的错误计数，协商失败时持续增长 | 04 |
| 自协商失败 | 两端速率或双工不匹配，端口可能 up 但性能一塌糊涂 | 04 |
| 管理面 / 带外 | 独立于业务转发的一张网，只用来管设备，与「设备在不在干活」是两回事 | 08 |

| `ifName` / `ifAlias` | 端口名与描述，前者也变，后者由人维护，稳定度最高的是 CMDB 里的对象 ID | 16 |
| `ifAdminStatus` | 人给的状态。值 2 表示有人手工 shutdown | 04 |
| `ifOperStatus` | 链路给的状态。有七个取值，多数平台只认前两个 | 04 |
| `lowerLayerDown` | `ifOperStatus=7`，本层没起来、原因在下一层，指方向的关键线索 | 04 |

## 采集与协议

| 术语 | 一句话 | 课 |
|---|---|---|
| SNMP | 设备管理协议，最老、最广、最不体面的一层，经常是唯一开放的接口 | 16 |
| OID | 树形命名空间里的一个点，一个指标一个点 | 16 |
| MIB | OID 的语义定义文件，决定你知不知道自己在读什么 | 16 |
| `ifTable` / `ifXTable` | 接口的标准表，前者给状态与计数器，后者补 64 位计数器与别名 | 16 |
| GetBulk | SNMP v2c 起的批量取值，按列走，设备 CPU 的主要压力来源 | 17 |
| walk | 遍历一张表。一次 `ifTable` walk 是几百行，万级设备要分片 | 16 |
| Trap | 设备主动上报的事件，秒级但会丢，必须与轮询对账 | 07 |
| syslog | 设备日志，比 Trap 多说几句、也多几倍噪声 | 29 |
| gNMI | 新一代设备接口，支持订阅，毫秒级但设备支持度不一 | 19 |
| on-change 订阅 | 值变化才推一次，快，连接断了会漏 | 19 |
| sFlow | 采报文样本（每 N 个包抓一个包头）+ 接口计数器 | 20 |
| NetFlow / IPFIX | 采流记录（五元组收敛后统计字节与包数），与 sFlow 是两种东西 | 20 |
| 采样率 | 1:1000 意味着 TopN 可信、小流完全不可见 | 21 |
| 流模板 | NetFlow v9 / IPFIX 的字段定义，会过期，过期之后那段数据不可信 | 22 |
| ARP 表 | IP 到 MAC 的映射，只在网关上有，老化时间决定查询能不能查到 | 27 |
| FDB / MAC 表 | MAC 到端口的映射，核心交换机几十万条，要限速采 | 27 |
| DHCP 租约 | 「这个 IP 分给谁了」，ARP 查不到时的补充源 | 27 |
| LLDP / CDP | 邻居发现协议，设备拓扑的主要来源，默认经常是关的 | 26 |
| STP | 生成树，能给出二层树的形状，看不出物理冗余 | 26 |
| textfsm | 命令输出解析的模板方案，按厂商与版本分别维护 | 45 |

## 探测与测量

| 术语 | 一句话 | 课 |
|---|---|---|
| 探针 / agent | 主动发探测包的程序，装在服务器上，自己也会出故障 | 15 |
| PingMesh | 在全网服务器之间铺满主动探测，用矩阵衡量网络质量 | 11 |
| 探测矩阵 | 谁探谁、多久一次的调度表，同机架不探、上行必探、层间抽样 | 11 |
| 覆盖率 | 已探 ÷ 应探，分链路覆盖率与任务覆盖率两个数 | 10 |
| 举证包 | 输入时间窗与路径、输出一页结构化证据的只读接口，五个字段组 | 10 |
| INT / 带内遥测 | 让数据包自己携带每一跳的入口、出口、队列深度、时间戳 | 13 |
| RTT | 往返时延。TCP 建连耗时里掺着对端处理时间，不是纯网络时延 | 15 |
| p50 / p99 | 分位数。均值回答「大多数人怎么样」，p99 回答「最差的那批怎么样」 | 00 |
| 丢包率 | 至少三种算法（探测失败率、计数器丢弃比、误码推算），差一个数量级 | 36 |
| 抖动 | 时延的变化幅度，与丢包是两件事，判据也不同 | 36 |
| 微突发 | 持续毫秒级、峰值远超均值的流量突发，60 秒轮询看不见 | 40 |
| traceroute / mtr / paris | 三个路径工具，分歧在 ECMP 与流标签，中间跳丢包多半是 ICMP 限速 | 43 |
| tcpdump / tshark | 抓包，重点是过滤器设计与三处对照，不是语法 | 42 |
| ethtool | 看网卡侧丢包（`rx_dropped`、`rx_fifo_errors`）与 ring buffer | 44 |
| ring buffer | 网卡接收环，默认 256，万兆下是常见瓶颈 | 44 |
| offload（TSO/GRO） | 网卡卸载，开着时抓到的分段与线上真实分段不是一回事 | 44 |

## 数据与存储

| 术语 | 一句话 | 课 |
|---|---|---|
| 时序库 | 写多读少、按时间组织的存储，选型的约束不在写入峰值 | 34 |
| 序列 / series | 一组标签值唯一确定的一条时间线，基数爆炸就炸在这里 | 37 |
| 标签 / label | 指标的维度。四类：身份、属性、业务、采集 | 37 |
| 基数 | 不同标签值的组合数，每加一维乘一次 | 37 |
| 排序键 | 决定一条查询能跳掉多少行（跳数） | 34 |
| 分区键 | 决定一次查询要开几扇门（扫几个分区） | 34 |
| TTL | 保留期，成本的第一大旋钮 | 34 |
| 降采样 | 把细粒度数据滚成粗粒度，标签够多时省不回成本 | 35 |
| granule | 列式库的最小索引单位，默认 8192 行，稀疏索引只说「这 8192 行里可能有」 | 34 |
| 水位线 | 流处理的「等到什么时候可以关闭窗口」，宽度由控制面的最大补报延迟推出 | 33 |
| 窗口 | 聚合的时间边界，窄了丢数据，宽了延迟可见 | 33 |
| 幂等键 | 去重的依据。拉取式取 `(probe_id, batch_seq, metric_id)` | 33 |
| 批次号 / 位点 | 拉取式上报自带批次；位点是已确认的最大批次号，只存在服务端 | 30 |
| Protobuf | 二进制编码，省的是键名与边界；压缩之后优势会消失 | 33 |

## 平台与运维

| 术语 | 一句话 | 课 |
|---|---|---|
| CMDB | 主数据：设备、端口、链路、终端的名字与归属。它错了后面全错，且错得隐蔽 | 23 |
| 台账 | CMDB 里人工维护的那部分，必然滞后，所以要对账 | 24 |
| 僵尸 / 幽灵 / 错挂 | 台账有现网无、现网有台账无、两端描述对不上，三类差异 | 28 |
| 生命周期状态机 | 规划→到货→上架→在网→维护→下线→报废，只有「在网」与「维护」产生告警 | 24 |
| 对账 | 台账与现网比对，产出差异单，**不自动改写台账** | 28 |
| 影响面分析 | 沿拓扑与业务归属向上传播，回答「这次动了什么、谁会受影响」 | 28 |
| 变更窗口 | 变更单的起止时间 + 设备清单，窗口内的告警降级但不丢弃 | 28 |
| 割接 | 计划内的网络调整，最典型的失败是漏项，不是割接本身砸了 | 02 |
| 父子告警 | 父压制子，不反向。板卡重启是父，49 条端口 down 是子 | 38 |
| 抑制 | 靠对象图上的依赖关系压掉下游告警，血缘缺失时退化成时间窗关联 | 38 |
| 静默 / silence | 人工静音，必须有到期时间与原因，最长 7 天 | 38 |
| 基线 | 相对自身历史或横向同类比较，解决静态阈值必然误报的问题 | 39 |
| 阈值 | 一个数与一条线的比较。定在哪里都错，只能定在「误报可忍受」的位置 | 39 |
| 五种形态 | 阶跃、漂移、尖刺、锯齿、缺失，各指向不同的排查方向 | 40 |
| SLO / SLA | 承诺与内部目标。分母定不清，两边算出来就不是一个数 | 49 |
| 定级 | 影响多大、叫谁。它是信息密度问题，不是判断力问题 | 02 |
| 复盘 | 拼时间线，问「为什么那时候才发现」。结论退化成「加强监控」就说明数据不够 | 55 |
